# dlt-hub Verified Sources Survey

Survey of 10 connectors in `dlt-hub/verified-sources` to extract ingestion patterns reusable when building a custom dlt source. Each connector was read directly from its `__init__.py` (and selected `helpers/` files) via `gh api`.

## Common patterns

1. **`@dlt.source` returns multiple `@dlt.resource`s.** Almost every connector exposes one source per logical API surface (auth domain), and each source returns N resources — one per endpoint/entity. Resources are typically defined *inside* the source so they capture the shared client and config in closure.
2. **Secrets via `dlt.secrets.value` defaults on source kwargs.** No connector reads env vars directly. They declare `api_key: str = dlt.secrets.value` (or `dlt.config.value` for non-secret config), letting dlt's config system resolve from `secrets.toml`, env, or vault.
3. **Incremental loading via `dlt.sources.incremental` on the resource signature.** The cursor is a kwarg default, not module state. Almost every incremental resource cursors on a server-side `updated_at` / `SystemModstamp` / `created` field and uses ISO strings or `pendulum.DateTime`.
4. **`primary_key="id"` + `write_disposition="merge"`** is the canonical pair for mutable entities. Reference/static tables use `replace`. Append-only event streams use `append` + `primary_key="id"`.
5. **A thin helpers module owns transport.** Pagination, retry, rate-limit, auth refresh all live in `helpers.py` / `helpers/client.py`. The `__init__.py` is declarative — it just wires resources to helper functions.
6. **Pagination is encapsulated as a generator.** `client.get_pages(endpoint, params)` is the dominant shape; the resource body is usually a one-liner `yield from client.get_pages(...)`.
7. **`allow_external_schedulers=True`** is set on all production-grade incrementals (Zendesk, Shopify) so Airflow can pass `start`/`end` windows.

## Divergences

1. **Schema contract:** *Nobody* in the surveyed set declares an explicit `schema_contract={...}` (freeze/evolve/discard). The defaults (evolve) are accepted. Type discipline is enforced two other ways: (a) per-column `columns={"end_time": {"data_type": "timestamp"}}` hints on the decorator (chess), or (b) runtime hints via `dlt.mark.with_hints(make_hints(columns=...))` derived from API metadata (HubSpot). This is a notable gap worth filling for our own sources.
2. **Credential shape:** flat kwargs (Jira: three `dlt.secrets.value` parameters) vs. a typed `@configspec` `CredentialsConfiguration` union (Zendesk, Salesforce). The `@configspec` Union pattern lets one source accept multiple auth strategies (basic / token / OAuth) and is what to copy when supporting more than one auth flow.
3. **Cursor field:** ISO datetime string (most), `pendulum.DateTime` (Shopify), UNIX int (Stripe), or *no* incremental primitive at all (chess uses `resource_state()` to track visited archive URLs — a poor man's incremental for non-time-ordered data).
4. **Replace vs. merge on mutable data:** Salesforce treats `Contact`/`Lead`/`Campaign` as `replace` (no `LastModifiedDate` filter wired) even though they are mutable — a pragmatic call where the entity is small and the API has no cheap cursor. Stripe goes further: two whole source variants (`stripe_source` replace vs. `incremental_stripe_source` append) push the choice onto the caller.
5. **Schema discovery:** `sql_database` reflects schema from SQLAlchemy `MetaData` (`reflection_level` param), HubSpot derives column types by calling the properties API first, everyone else accepts whatever JSON the API returns and lets dlt infer.

## Production wisdom

- **Put transport in `helpers/`. Keep `__init__.py` declarative.** Resources should read like a manifest, not a script.
- **Default to `merge` + `primary_key="id"` + an `updated_at` incremental** for any mutable entity. Use `replace` only for small reference tables or APIs without an updated cursor.
- **Make incremental optional, not required.** Provide `initial_value=None` so the first run is a full load; provide `end_value` so backfills are bounded.
- **Pass `allow_external_schedulers=True`** on every incremental — costs nothing, unlocks Airflow.
- **Wrap multi-auth in a `@configspec` `Union[...]`** rather than booleans. Zendesk's `TZendeskCredentials` and Salesforce's `SalesforceAuth` are the templates.
- **Pin API version explicitly** (`stripe.api_version = "2022-11-15"`, Shopify `DEFAULT_API_VERSION`). Never let the upstream pick.
- **Use `columns={...}` decorator hints for date/timestamp columns** the API returns as strings — dlt's inference is unreliable for ISO strings with tz offsets.
- **Set `max_table_nesting=2` on the source** unless you truly want recursive child tables. Most APIs return one level of nested objects; deeper auto-fanout creates schema sprawl.
- **Break the page loop early on `start_out_of_range` / `end_out_of_range`** to save API quota — dlt would skip the rows anyway, but you save the HTTP cost.
- **Don't return `dlt.resource(...)(args)` from a `@dlt.source` loop** with a closure over the loop variable — bind via the resource call (`(endpoint)` at the end of `dlt.resource(...)(endpoint)`), as Stripe does, otherwise late-binding bites you.
- **Consider declaring `schema_contract="evolve"` (or `"freeze"`) explicitly** — none of the verified sources do, and it's a real gap if you care about downstream stability.
